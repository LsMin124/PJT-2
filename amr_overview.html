SEC 00 · 한눈에 보기

데이터가 들어와, 곡선이 되어 나간다

"물류센터의 시설·물류 데이터를 받아, 시뮬레이션으로 AMR 대수별 처리량–비용–ROI를 투명하게 산출하고, 고객이 곡선 위에서 직접 도입 규모를 선택하게 하는 중립 견적 SaaS." — 제품 한 줄 정의

시스템 전체 지도

위쪽이 견적 본체(빠른 시뮬레이션 수백 런), 아래쪽이 검증 트랙(정밀 3D 재현 1~2런)입니다. 주황 상자(단일 내부 표현)가 전 컴포넌트가 공유하는 계약입니다.

먼저 알아둘 용어 8개 — 펼쳐 보기
용어쉬운 설명
AMRAutonomous Mobile Robot. 스스로 길을 찾아 다니는 물류 운반 로봇. 이 서비스가 견적을 내주는 대상
견적 SaaS웹에서 데이터를 넣으면 "몇 대를 사면 되는지"를 시뮬레이션으로 계산해 주는 구독형 서비스

반송/피킹 보조물건·카트를 옮기거나 피킹 작업자를 보조하는 방식. 인프라 변경 없이 3~15대 점진 도입 — v1 타겟 카테고리

스윕 · 시드기종·대수 조건을 바꿔가며 수백 번 돌리는 것(스윕)과, 같은 무작위 시나리오를 재현하게 하는 난수 시작값(시드)

SEC 01 · 제품 정의

선택은 고객이, 근거는 시스템이

판매자의 블랙박스 견적이 놓여 있던 자리에, 가정·과정·불확실성을 전면 공개하는 중립 시뮬레이션을 놓습니다.

잠재 고객창고를 보유하고 AGV/AMR 자동화 전환을 검토하는 모든 사업체
핵심 차별점벤더 견적은 팔기 위한 숫자 — 우리는 가정과 과정을 전부 보여주는 중립 시뮬레이션의 숫자
제품 철학선택은 고객이, 근거는 시스템이

왜 v1 타겟이 반송/피킹 보조 카테고리인가

시장 1위인 GTP(~38%)는 벤더 턴키 거래라 중립 견적의 자리가 없고, 반송/피킹 보조(~25~27%)는 기존 창고에 3~15대를 점진 도입하는 구조라 견적 의사결정이 실제로 일어납니다. 시장 근거와 "왜 GTP가 아닌가" 문답의 상세는 APPENDIX A · 시장 근거 참조.

SEC 02 · 2계층 시뮬레이션

빠르게 계산하고, 물리로 검증한다

SEC 04 · 계약

인터페이스 4개를 동결해야 병렬이 시작된다

계약이 동결되어야 여섯 명이 서로 기다리지 않습니다 — 주 1~2차의 크리티컬 패스입니다.

① 입력 JSON 스키마시맨틱 그리드 + 수요 프로파일 + 운영 설문 — 시스템 전체의 계약
② Kafka 이벤트 스키마시뮬레이션 결과·진행률이 흐르는 형식
③ 디스패처 인터페이스규칙·휴리스틱·RL을 갈아끼우는 경계
④ VDA 5050 서브셋검증 트랙과 v2 확장의 인터페이스 (2.0 · order/state/connection + instantActions)

SEC 05 · 인테이크

요구 데이터는 최소로, 전환율은 최대로

견적 품질은 입력 품질을 넘지 못하므로, 고객이 낼 수 있는 데이터 수준에 맞춰 문을 3개 둡니다.

티어시설 데이터수요 데이터v1
T1웹 에디터로 직접 작도폼 6개 숫자 → 러프 견적포함
T2도면 PDF/이미지 오버레이 + 2점 축척 보정 + 트레이싱자체 엑셀 템플릿(주문시각·주문ID·SKU·수량) → 프로파일 자동 추출포함
T3DXF(CAD) 임포트 + 반자동 태깅WMS API 연동로드맵
  • 요구 데이터 최소화(전환율) · 개인정보 컬럼 비수집(신뢰) · 최소 2주~1개월치 · 피크 포함 여부 확인
  • CAD 자동 파싱을 v1에서 뺀 근거 — 진짜 비용은 파싱이 아니라 시맨틱 복원. 상용 시뮬레이터도 "배경 참조 + 수동 배치"가 관례
  • T1 퍼널 — 러프 견적을 먼저 보여주고 "정밀 견적은 데이터 업로드 시"로 유도
SEC 06 · 기종 결정

카테고리는 룰이 거르고, 대수는 스윕이 정한다

원칙: 카테고리 = 시뮬레이션 모델 템플릿, 기종 = 파라미터.

  • 1단 · 카테고리 게이트(룰) — 하드 제약(반송 단위·중량, 통로 폭, 환경) + 소프트 신호(SKU×주문 구조, 재설계 수용성) → 권장/배제 + 배제 사유 명시. 투명성 서사의 일부
  • 2단 · 카테고리 내 스윕(정량) — 카탈로그 필터 → 기종 × 대수 2차원 스윕 → 등처리량 곡선 비교 ("A 기종 5대 = B 기종 7대")
항목결정
정밀 모델 범위v1 반송/피킹 보조 · v1.5 팔레트 · v2 GTP — 게이트는 v1부터 전 카테고리 커버("판단은 넓게, 정밀 견적은 좁게"), GTP 적합 고객은 벤더 직행 안내
검증 기종iw.hub 메인 · MiR 250 서브(이기종 데모) · Nova Carter는 스모크 테스트용
견적 카탈로그커버리지 기준 4~6종, "풀스택 검증 / 파라미터 산정" 배지로 신뢰 수준 구분
SEC 07 · 출력 설계

고객은 곡선 위에서 고른다

최종 산출물은 숫자 하나가 아니라 선택할 수 있는 곡선입니다.

한계효용 곡선곡선이 꺾이는 지점 = 병목의 이동 → "로봇 추가 대신 스테이션 증설" 조언으로 (원리: MAIN 04)
TCO 중첩 → ROI 최적점비용 곡선을 겹치고, 곡선 위 클릭 = 그 구성의 상세 리포트
통계적 정직함다중 시드 + 95% 신뢰구간 병기 · 워밍업 절단 · 민감도(OAT)
투명성 3겹가정 명세(수정 가능) / 과정(병목·대기열 분해) / 불확실성(신뢰구간·민감도)
SEC 08 · 마일스톤

8주 — 견적을 먼저 완성한다

최악의 경우에도 완결된 견적 데모가 남도록, Isaac 검증은 마지막에 붙입니다.

파랑 = 견적 본체 구축, 초록 = 검증 트랙, 주황 = 통합·발표. 검증(M4)이 견적(M1~M3) 뒤에 오는 것이 생존 전략입니다 — 주차별 산출물과 생존 원칙 상세는 MAIN 03 · 로드맵 참조.
