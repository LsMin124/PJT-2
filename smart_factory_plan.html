SEC 01

프로젝트 정체성과 목표

ONE-LINE DEFINITION"멀티로봇 시뮬레이션 기반 생산 셀을 구축하고 ISA-95 계층으로 MES까지 통합한 스마트팩토리 솔루션"

"로봇 프로젝트에 백엔드를 붙인 것"이 아니라 제조 IT/OT 통합 시스템에서 물리 레이어를 시뮬레이션으로 구현한 것. 타겟 직무는 삼성 생산기술연구소·SEMES·LG 생산기술원·현대위아 등 제조/설비 SW R&D.

전략적 배경

  • 하드웨어 없이 시뮬레이션 온리로 기술 스택 완성 — 실기체 경험은 도도 프로젝트가 이미 커버, 반복 증명 불필요
  • 실기체(sim-to-real)는 사이드로 열어두되 시뮬 단계 완성 후 전이
  • 포트폴리오 상호보완: 도도(실기체·비전·엣지) + 본 프로젝트(시뮬·제어·산업 통합)
  • 어느 단계에서 멈춰도 완결되도록 단계 설계 — 리스크 통제

SEC 04

SimPy × Isaac Sim 정합성과 통합

근본적 차이 — 시간 패러다임

SimPy — 이산사건(DES)

  • 시간: 사건→사건 점프, 사이 구간 미계산
  • 속도: 하루치를 수 초에, Monte Carlo 수천 회
  • 관심사: 흐름과 자원 — 처리량·병목·대기열

Isaac Sim — 연속시간 물리

  • 시간: 고정 타임스텝(1/60s 등) 연속 적분
  • 속도: 실시간 ~ 수 배속
  • 관심사: 운동과 상호작용 — 파지·충돌·센서

→ 하나의 시계로 강결합 금지: DES의 장점(초고속·통계 반복)이 물리 속도에 묶여 소멸.

정합 패턴 3단계 — 점진 승격 구조

캘리브레이션 결합 OFFLINE · 우선

Isaac에서 단위 작업 반복 측정(픽앤플레이스 200회 → 평균 12.3s, σ=1.8s, 실패율 4%) → SimPy 공정 파라미터로 주입. 실행 완전 분리·단방향. "물리적 근거를 가진 공장 모델" — 산업 디지털 트윈 표준 구조. what-if 실험 자유(AMR 3대 vs 4대, 배차 A vs B).

▼ 승격

계획-실행 분리 ONLINE · 데모 핵심

SimPy = 실시간 페이싱되는 오케스트레이터(작업 도착·큐·배차 결정). 명령은 MQTT(VDA 5050 order) → Isaac 물리 실행 → 완료 이벤트 회신 → 다음 사건 트리거. 내부 예상 소요시간은 버리고 외부 완료 이벤트 대기 → 사실상 이벤트 기반 잡 스케줄러화.

▼ 승격

하이브리드 FINAL FORM

Isaac에 있는 셀 = 패턴 2 실제 실행, 나머지 셀 = 패턴 1 분포로 가상 처리. 물리 셀 + 통계 셀 공존 = VRAM 예산 해법이자 브라운필드 공장 디지털 트윈과 구조 동일. 실기체 편입 시 "실물 셀 1개 추가"로 자연 확장.

정합성 설계 원칙

  • 시간 권위 단일화 — 라이브 통합에서는 벽시계(Isaac 실시간)가 권위, SimPy가 추종
  • 경계는 이산 사건만 — 오더 발행/완료/실패만 교환. 연속 상태(관절각·좌표)는 Sparkplug B로 DB/Grafana에만
  • 실패 의미론 통일 — Isaac 파지 실패 = SimPy에서 재시도/불량 분기 동일 정의
  • 결정론 포기 + 전 사건 타임스탬프 로깅으로 사후 재구성 확보

SEC 06

단계별 로드맵

PRINCIPLE수직 슬라이스 우선 — "스테이션 1개 + AMR 1대 + 데이터 경로 끝까지"를 최소 구성으로 먼저 관통, 이후 수평 확장. 통합 리스크를 앞에서 흡수.
PHASE 0

데이터 백본 (Isaac 없이 시작, 5060 Ti 가능)

SimPy 물류 모델(가짜 분포) + Spring MES-lite + MQTT 브로커 + TimescaleDB/PostgreSQL + Grafana · VDA 5050/Sparkplug B 스키마 설계

PHASE 1

ROS2 코어 (Gazebo)

LeKiwi+SO-101 통합 URDF · ros2_control(베이스 velocity/팔 position) · Nav2 + EKF + MoveIt2 · behavior tree로 주행→도킹→픽앤플레이스

PHASE 2

Isaac Sim 포팅 + 수직 슬라이스 완성

USD 변환·ROS2 브리지로 노드 재사용 · 셀 1 + AMR 1 라이브 접속(패턴 2) · Replicator 결함 데이터 → QA 모델 → 폐루프

PHASE 3

Isaac Lab RL

파지(또는 도킹 정렬) 1태스크: 환경 정의 → 도메인 랜덤화 → PPO → 평가 · STS3215 실측 스펙 반영 · 검증 서사 = sim-to-sim 전이 + 랜덤화 민감도 분석 · 소규모(64~128 env) 검증 → 야간 대규모(2048+) 본 학습

PHASE 4

수평 확장 + 시뮬 CI

셀/AMR 추가(하이브리드) · 배차 알고리즘 비교(consistent hashing/Power of Two Choices) · Jenkins headless 회귀 CI: 표준 시나리오 자동 실행 → 사이클 타임/성공률 리포트

PHASE 5 · 선택

Sim-to-Real 사이드

SO-101 + LeKiwi 실기체를 "실물 셀 1개"로 편입 → 하이브리드 디지털 트윈 완성형

이론 학습 전략 — Just-in-Time

원칙: 교과서 정주행(현대제어·라그랑주 동역학 등)은 오버. 프로젝트 단계가 이론을 소환하는 시점에 최소 구현으로 학습. 별도 트랙 없음.

프로젝트 단계소환되는 이론최소 구현 과제
옴니휠 베이스 제어기구학 — 키위 드라이브 역기구학, 홀로노믹/자코비안3륜 속도↔(vx,vy,ω) 변환 행렬 직접 유도 + numpy 검증 ~1일
ros2_control 튜닝제어공학 — PID1차/2차 시스템 Python PID 시뮬, 게인별 응답 관찰 ~2-3일 유일한 선행 학습
MoveIt2 매니퓰레이션로봇공학 — FK/IK, DH, 특이점SO-101 URDF 순기구학 numpy 계산
EKF 센서 퓨전상태추정 — 칼만 필터1차원 칼만 필터 직접 구현 ~반나절
Isaac Lab RL동역학 맛보기랜덤화 실험으로 체감 (깊이 불요)
  • 운용 리듬: "이번 주 작업에 등장한 이론 하나를 주말에 최소 구현으로 정리" → 산출물이 그대로 설계 근거 문서/기술 블로그
  • 효과: "기계 출신인데 SW 하는 사람" → "로봇공학을 실제로 하는 사람"으로 읽히게 하는 재료
  • Modern Robotics 등은 정독이 아닌 사전(해당 챕터만) 용도
SEC 09

핵심 결정 사항 — Decision Log

프로젝트 정체성 = 시뮬 기반 제조 IT/OT 통합 시스템 (로봇 단독 프로젝트 아님)
매니퓰레이션 = MoveIt2 고전 접근이 본체, RL은 심화 챕터
시뮬레이터 = Gazebo(개발 무대) + Isaac Sim(합성 데이터·물리 셀) + Isaac Lab(RL 1태스크) + SimPy(물류 DES)
버전 고정 = Isaac Sim 5.x / Isaac Lab main / Python 3.11 (Blackwell 제약)
머신 역할 = 5080 Ubuntu 전담 워크스테이션, 5060 Ti Windows는 원격 클라이언트 (데일리 보존)
산업 표준 = 설비 텔레메트리 Sparkplug B / AMR 운송 VDA 5050
SimPy×Isaac 통합 = 캘리브레이션 → 라이브(계획-실행 분리) → 하이브리드 점진 승격
역량 배분 = 로봇/시뮬 50 / 산업 통합 30 / 기타 20
개발 순서 = 수직 슬라이스 우선, 데이터 백본 먼저 (Phase 0)
실기체 = SO-101+LeKiwi, STS3215 1/345 ×9(+예비), 12V 통일, 리더 암 불필요, 구매 트리거는 RL 정책 안정화 시점
URDF는 처음부터 실기체(LeKiwi+SO-101) 기준으로 고정
이론 학습 = just-in-time, 선행은 Python PID 시뮬 2~3일만
