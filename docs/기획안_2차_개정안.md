# 산타팩토리 — 기획안 2차 (개정본)

> 3PL 물류센터의 운영 조건을 입력받아 AMR 수량별 운영 성능을 시뮬레이션하고,
> 목표 처리량을 만족하는 적정 대수 · 예상 구축비용 · 운영 KPI를 제시하는 B2B 의사결정 지원 서비스

- 팀 루돌프(A106) — 팀장 신재령 · 팀원 김소희 김형수 박화랑 이승민 최아영
- 문서 상태: 2차 기획안 개정본 (2026-08-25) · 원본 대비 변경점은 아래 "개정 요지" 참조

---

| 항목 | 원본 (2차) | 개정본 |
|---|---|---|
| 서술 방식 | 서술형 문단, 절 간 논리 중복 다수 | 개조식 · 표 중심, 중복 제거 |

## 1. 배경과 문제 정의

### 1-1. 배경

- 3PL 물류센터: 판매자로부터 입고 → 보관 → 주문 처리 → 피킹 → 포장 → 출고를 위탁 수행
- 수익 구조는 **건당 과금**(입고 팔레트당 · 보관 팔레트월당 · 출고 주문건당) → AMR 대수 결정은 곧 **건당 처리 원가** 문제
- 피킹·내부 운반에서 발생하는 작업자 이동시간이 처리 성능의 병목 → AMR로 반복 운반을 자동화

### 1-2. AMR 대수 산정이 어려운 이유

1. **센터별 조건 상이** — 레이아웃, 랙 배치, 시간당 주문량, 주문당 SKU 수, 작업자 수, 피킹 속도가 전부 다름. 타 센터의 도입 대수를 이식해도 같은 성능 보장 불가
2. **평시/피크 이중 기준** — 평시 기준 산정은 피크 시간대 처리량 미달, 피크 기준 산정은 평시 저가동·과잉 투자
3. **수확 체감** — 통로·교차로 혼잡으로, 대수를 늘린 만큼 처리량이 비례해 늘지 않음
4. **정적 계산의 한계** — 주문 발생 시점, Task 배정, 상품 위치, 경로 간 상호작용은 수식이 아닌 시뮬레이션의 영역

### 1-3. 핵심 질문

> **"이 센터의 운영 조건과 예산 범위에서, 목표 처리량을 만족하는 최소 AMR 대수는 몇 대인가"**

## 2. 해법 — 2계층 시뮬레이션

### 2-1. 구조

| 계층 | 도구 | 역할 | 방식 |
|---|---|---|---|
| **1차 · 견적 스윕** | SimPy 이산사건 시뮬레이션(DES) | 대수 1~N을 반복 실행, KPI 측정, 후보 대수 선정 | 넓고 얕게 — 수십 구성 고속 비교 |
| **2차 · 물리 검증** | Isaac Sim + ROS2 | 선정 후보 구성만 3차원 검증 — 다수 AMR 이동, 통로 혼잡, 교차로 병목 | 좁고 깊게 — 대표 구성 정밀 확인 |

- **권장 대수 선정 기준(MVP): 목표 처리량 충족 ∧ 예산 이내 ∧ 최소 대수**
- 가동률·대기율·평균 처리시간은 추천 수량의 상태 설명 및 인접 수량 비교용 보조 지표

### 2-2. 환류 원칙

- 2차 물리 시뮬의 실측값(가감속, 구간 주행시간, 반송 사이클 타임, 다중 로봇 간섭)을 **1차 DES 파라미터 보정으로 환류**
- 물리 시뮬은 시연 영상 장치가 아니라 **견적 숫자의 신뢰도 장치** — 환류 없는 물리 시뮬은 수행하지 않음

### 2-3. 업계 정합 — Virtual Commissioning

- 이 방식은 업계 표준 관행인 **가상 시운전(Virtual Commissioning)**의 SiL 구성과 동형 — 실제 제어 소프트웨어(FMS)를 가상 플랜트에 물려 도입 전 검증
- 표준: [VDI/VDE 3693](https://www.vdi.de/en/home/vdi-standards/details/vdivde-3693-blatt-1-virtual-commissioning-model-types-terms-and-definitions) (모델 유형·용어)
- 선례: Siemens가 [AGV 시스템 가상 시운전](https://blogs.sw.siemens.com/tecnomatix/plant-simulation-software-virtual-commissioning/)과 [가상 환경 AMR 함대 규모 평가·최적화](https://www.siemens.com/en-us/products/simove/fleetmanager/)를 공식 워크플로로 제공 — 본 서비스가 서는 지점과 동일

### 2-4. 기준 기종 — iw.hub 고정

- idealworks(BMW 그룹) **iw.hub** 1종으로 고정 — 성능·단가를 이 기종 기준으로 산정
- 선정 근거: 후보군 중 유일한 **공식 Isaac USD 배포 기종** + 팀 장비에서 실구동 검증 완료(2026-08-24) + 반송형으로 v1 타겟과 일치
- 기종 간 성능·가격 비교는 확장 범위 (프로파일 구조는 다기종 확장 가능하게 설계)

## 3. 시스템 구성

### 3-1. 파이프라인

```
웹 입력 → 주문·Task 변환 → FMS(배정·경로·혼잡 관리) → 시뮬(1차 DES / 2차 물리) → 결과(추천 대수·구축비·KPI)
```

### 3-2. 입력

| 분류 | 항목 |
|---|---|
| 공간 | 이동 가능 영역, 랙 위치, 피킹 스테이션 위치 |
| 주문 | 시간당 주문량, 주문당 평균 SKU 수, 피크 주문량 |
| 운영 | 작업자 수, 평균 피킹 시간 |
| 장비 | AMR 이동속도·적재능력 (iw.hub 고정값) |
| 제약 | 목표 처리량, 최대 구축 예산 |

### 3-3. 측정 KPI

| 분류 | 지표 |
|---|---|
| 처리량 | 시간당 주문 처리량, 시간당 피킹량 |
| 시간 | 평균 주문 처리시간, 통로 대기시간 |
| 로봇 | 가동률, 대기율, 미션 완료율, 이동거리 |

### 3-4. 표준 스택

| 계층 | 선택 | 비고 |
|---|---|---|
| 1차 시뮬 | SimPy (Python DES) | 대수 스윕 엔진 |
| 2차 시뮬 | Isaac Sim 6.0 + ROS2 Humble + Fast DDS | 물리·센서 충실도 |
| 로봇 실행기 | Nav2 컨트롤러 모드 | 경로는 FMS가 하달, 로봇은 추종 + 국지 회피 |
| 로봇↔FMS 경계 | VDA 5050 / MQTT | 산업 표준 인터페이스 — 실로봇 연동 확장 경로 |
| 서비스 스택 | 팀 명세 준수 (RabbitMQ 잡 큐 등) | 상세는 명세서 기준 |

- **경계 원칙**: 경로 계획은 중앙(FMS) 전담, 로봇의 자율 재계획 없음 — 상용 FMS·VDA 5050과 같은 구조

## 4. 구현 범위

### 4-1. 범위 경계

| 포함 | 제외 |
|---|---|
| 주문 접수 이후 피킹·내부 운반 공정 | 입고·검수·포장·배송 공정 |
| 단일 기종(iw.hub) 대수 스윕 | 기종 간 비교 (확장) |
| 예상 구축비용 산정 (단가 × 대수 + 정의된 구축비) | 자재 관리비 등 간접 비용 |
| 가상 주문 데이터 생성 | 실제 도면 자동 변환, 실제 배송 |
| — | 재고 부족 상황 (무한 재고 가정) |

### 4-2. MVP 기능

| 파트 | 기능 |
|---|---|
| **FMS** | Fleet 구성(스윕 대수 N), AMR 상태 관리(Idle/Moving/Picking/Waiting/Charging), Task 큐(우선순위), 가용 AMR 배정, 경로 계획, 충돌·혼잡 관리(통로/교차로 대기) |
| **시뮬레이션(1차)** | 창고 맵 좌표계, 시나리오 적용(주문량·작업자·피킹 속도), FMS 연동, AMR 동작(이동·피킹·운반·충전, 이동량 기반 배터리), 처리량·가동률·혼잡도 측정 |
| **결과** | 대수별 KPI 비교, 권장 대수 + 예상 구축비용 제시 |

### 4-3. 병행 트랙 — 2차 물리 시뮬 (개정 포인트)

- 원본의 "여유 시 확장"에서 **로드맵 있는 병행 트랙으로 격상** — 시뮬 인력 2명 전담, 근거는 2-2·2-3
- 4태스크 로드맵: **T1** 텔레옵 1대(브리지 개통) → **T2** Nav2 자율주행 1대 → **T3** 물류 창고 씬 반송 사이클 → **T4** 다중 로봇 3~5대 + FMS 결합
- **축소선**: 일정 압박 시 T3까지만 수행해도 제품 성립(견적 + 단일 로봇 물리 검증). T4 미완 시 다중 로봇 수치는 DES 단독 + 문헌 근거로 대체

### 4-4. 확장 기능 (MVP 외)

| 파트 | 기능 |
|---|---|
| 결과 | 시각화 고도화(그래프·히트맵·대시보드), 견적서 PDF 출력, 기종 비교, 처리 여유율 |
| 시뮬 | 실시간 위치 스트리밍, 스트레스 테스트(한계 처리능력), AMR 장애 재현 + Task 재배정 |
| WEB Store | 시연용 주문 생성, 가상 주문 생성기, 상품 조회·장바구니·주문 상태·내역·취소 |
