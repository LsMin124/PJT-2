SEC 01 · 아키텍처

모든 컴포넌트는 하나의 계약만 바라본다

전체 그림은 MAIN 02 시스템 지도 — 여기서는 그 그림을 성립시키는 결정 세 가지입니다.

단일 내부 표현 = 계약인테이크가 어떤 형태로 들어와도 "시맨틱 그리드 + 수요 프로파일 JSON" 하나로 변환 — 이후 전부 이것만 바라본다
스윕 = K8s Indexed Job스윕 1회 = 잡 1벌, 인덱스 = 기종×대수×시드. Kafka→TimescaleDB 집계, Redis→WebSocket 진행률
경로는 중앙 하달VDA 5050 노드/엣지를 내려보내고 Nav2는 구간 주행만 — 아니면 두 계층의 정합성 비교가 무너진다

이 제품에 이르게 된 5단계 의사결정 여정과 교훈은 APPENDIX A · 확정 여정에 있습니다.

SEC 02 · 이론 기반

경합이 곡선의 모양을 결정한다

대수–처리량 곡선이 꺾이는 이유는 경로 경합이고, 그 수학이 MAPF입니다. 계보(A*→예약 테이블→Prioritized→CBS→RHCR)·문헌·집계 이론 전체는 MAIN 04 경로계획 이론 한 곳에서 다룹니다. 이 계획서에 남는 결정은 하나 — SimPy 계층에는 경량 MAPF를 내장(고정 틱, 1틱=1셀)하며, 매 틱 CBS는 배속을 파괴하므로 배제.

SEC 03 · AI 파트

휴리스틱이 기본, RL은 후퇴선 있는 연구다

디스패처 세 단계를 같은 조건에서 겨루게 합니다 — 유일하게 실패 가능성이 있는 연구 요소입니다.

단계방식역할
규칙FIFO + 최근접기준선(baseline). 주 1~2차 E2E 루프의 기본
휴리스틱헝가리안 배치 매칭제품 기본 탑재 후보 — 안정적이고 설명 가능
RLPPO + Stable-Baselines3연구 요소 — 성능 상한 탐색
  • 학습·검증 분리(sim-to-sim) — RL 학습은 SimPy-Gymnasium 환경에서, Isaac은 검증만
  • 평가 규칙 — 동일 시드 쌍대 비교, 학습/평가 시나리오 완전 분리
최대 연구 리스크 — RL 맵 일반화 견적 서비스는 고객마다 맵이 다릅니다. 특정 맵에서만 통하는 정책이면 제품이 성립하지 않습니다. 대응: 맵 불변 관측(작업까지의 경로비용·구역 혼잡도) 설계 + 랜덤 레이아웃 학습. 실패 시 후퇴선(사전 합의): "RL은 연구 항목, 제품 기본은 휴리스틱".
SEC 04 · 표준 스택

프로토콜이 아니라 방법론이 정체성이다

정체성이 "로봇을 움직이는 시스템"에서 "신뢰할 수 있는 분석"으로 이동하며, 표준도 방법론(검증·KPI·안전) 중심으로 재편했습니다.

표준역할채택 수준
VDI 3633DES 절차·V&V — 투명성 주장의 표준 준거필수
ISO 22400KPI 정의 — 리포트 용어집의 출처필수
ISO 3691-4안전 거동 → 시뮬 파라미터 출처 (낙관 편향 방지)강추
VDA 5050 (2.0)검증 트랙 인터페이스 + v2 호환. order/state/connection + instantActions유지
Sparkplug B가상 AMR 텔레메트리 — 역할이 얇음을 인정하고 축소축소
MassRobotics / OPC UA·ISA-95비교 검토 후 기각 / v2 백로그지식·백로그
SEC 05 · V&V

검산 없는 숫자는 내보내지 않는다

Verification은 "올바르게 구현했는가", Validation은 "현실을 닮았는가"입니다.

Verification보존 법칙(주문 수 일치) · Little's Law 검산 · 로봇 1대 극한 케이스의 해석해 대조
ValidationMAPF 공개 벤치마크 대조 · SimPy vs 에뮬레이션 3단 오차(주행시간→사이클타임→처리량) · 예측 오차 공개
문서화모든 가정·분포·보정 계수를 리포트 부록 "가정 명세서"로 — 투명성 주장의 실체
SEC 06 · 크리티컬 패스

이 7건을 동결해야 병렬이 시작된다

다른 모든 작업이 이 결정들 위에 서 있습니다. 상세 배경은 MAIN 05의 해당 섹션 참조.

CP 1

맵 표현 · 셀 크기 · 좌표계 단일 소스

미터 좌표를 원본으로, 1로봇 = 1셀. 전 컴포넌트가 종속되는 결정.

CP 2

시간 모델 — 고정 틱

1틱 = 1셀 이동. MAPF 예약 테이블·재계획·통계의 전제.

CP 3

경로 지시 — 중앙 하달

두 시뮬레이션 계층의 정합성이 성립하는 조건.

CP 4

RL 일반화 전략 + 후퇴선

맵 불변 관측 + 랜덤 레이아웃. 실패 시 휴리스틱 기본 탑재로 후퇴(사전 합의).

CP 5

K8s Indexed Job + 결과 저장 정책

집계 기본, 상세 로그는 대표 런만. 인프라 골격.

CP 6

RTX 5080 RTF 실측

검증 트랙이 감당할 수 있는 로봇 대수의 물리적 상한 확정.

CP 7

4대 계약 동결

입력 스키마 / Kafka 스키마 / 디스패처 인터페이스 / VDA 5050 서브셋 (MAIN 02 SEC 04).

SEC 07 · 로드맵

최악의 경우에도 완결된 데모가 남는다

타임라인 그림은 MAIN 02 SEC 08에 있습니다. 여기서는 주차별 산출물과 순서의 이유를 적습니다.

주차산출물이 순서인 이유
주 1–24대 계약 동결 + SimPy DES + 규칙 디스패처 (E2E 최소 루프) + RTF 실측계약이 동결돼야 4트랙이 병렬로 출발. RTF 실측이 검증 스코프의 상한을 정한다
주 3Kafka→DB→차트 + Scenario API + 에디터 골격데이터가 끝까지 흐르는 배관을 먼저 뚫는다
주 4–5휴리스틱+RL 디스패처, K8s 스윕, 곡선/리포트 화면, 카테고리 게이트견적 본체의 완성 — 여기까지가 "최악에도 남는 데모"
주 6–7에뮬레이션 검증 트랙 + 보정 루프 1회전 + 오차 분석완성된 견적을 검증으로 보강. Isaac이 마지막인 이유
주 8통합, VDI 3633 준거 리포트, 발표—
생존 원칙 ① Plan(견적) 먼저 완성 — 최악의 경우에도 완결된 데모가 남는다 ② Isaac은 마지막 — 검증은 보강이지 본체가 아니다 ③ what-if 라이브는 사수, 나머지(스윕·에뮬레이션)는 캐시·녹화 폴백을 준비한다.
