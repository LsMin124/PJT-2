IT/OT 융합Smart Factory · Smart Logistics Convergence

설비·로봇이 만드는 현장 데이터(OT)와 기업 정보 시스템(IT)을 연결해, 현장이 스스로 상태를 보고하고 지시를 받는 체계. 공장이든 물류센터든 "IT와 OT의 융합"이 본질이다.

OT(Operational Technology)는 물리 세계를 직접 움직이는 기술이고, IT는 정보를 다루는 기술이다. 두 세계는 쓰는 프로토콜·시간 단위·안정성 요구가 완전히 달라서 오랫동안 분리되어 있었다. 스마트팩토리·스마트 물류센터는 이 사이에 표준화된 데이터 파이프라인을 놓아 "현장에서 일어나는 일"을 실시간으로 위(경영·분석)까지 올리고, "위의 결정"을 현장까지 내리는 것이다.

이 프로젝트에서 — 물리 레이어(OT)만 시뮬레이션일 뿐, IT/OT를 잇는 데이터 플로우·백엔드·서비스는 실제 스마트 물류센터와 동일한 구조로 만든다. 이것이 "로봇 데모"와 다른 점이다.

풀필먼트 프로세스Fulfillment — 입고에서 출고까지

주문을 받아 상품이 고객에게 나가기까지 물류센터 안에서 일어나는 전 과정. 입고 → 적치 → 보관 → 피킹 → 검수 → 패킹 → 분류 → 출고로 이어진다.

핵심 파생 용어: SKU(Stock Keeping Unit — 재고 관리의 최소 단위, "품목 한 종류"), 웨이브(주문 여러 건을 묶어 한 번에 처리하는 배치 단위), 슬로팅(어떤 상품을 어느 로케이션에 둘지 정하는 배치 전략 — 잘 하면 이동 거리가 급감), Goods-to-Person(작업자가 선반으로 걸어가는 대신 AMR이 선반/토트를 작업자·로봇 앞으로 가져오는 방식 — Amazon Kiva가 대중화).

이 프로젝트에서 — 주문 등록부터 출고 실적까지 이 흐름 전체가 시연 시나리오다. AMR이 Goods-to-Person 운송을, 로봇팔이 피스 피킹을, AI가 검수를 담당한다.

ISA-95제조 시스템의 계층 표준

공장의 소프트웨어를 5개 층(L0~L4)으로 나누는 국제 표준. 아래로 갈수록 물리에 가깝고 빠르며(마이크로초), 위로 갈수록 경영에 가깝고 느리다(일 단위).

웹의 프론트–백–DB 계층처럼, 제조 SW에도 표준 계층이 있다. 각 층은 바로 위·아래하고만 대화하는 것이 원칙이며, 이 규율이 시스템을 교체 가능하게 만든다. 면접·실무에서 제조 IT를 논할 때의 공용어이기도 하다.

이 프로젝트에서 — 계층적 사고의 틀로 사용한다. L0~2를 Isaac Sim(가상 물류센터)이 담당하고, L3 자리에 물류의 실행 계층인 WMS/WES-lite + SimPy 오케스트레이터가 놓인다(WMS·WES·WCS 참조).

WMS · WES · WCS물류센터의 소프트웨어 계층

물류센터 소프트웨어의 3층 구조. WMS는 "무엇이 어디에 얼마나"(재고·주문의 장부), WES는 "지금 누가 무엇을"(작업 오케스트레이션), WCS는 "설비를 어떻게"(컨베이어·소터 제어)를 담당한다.

제조의 MES(별도 항목)가 하던 역할이 물류에서는 WMS(장부)와 WES(실행)로 나뉜다. 최근 로봇 도입이 늘며 WES의 비중이 커지는 추세다 — 사람·AMR·소터에게 실시간으로 일을 나눠주는 계층이기 때문이다.

이 프로젝트에서 — Spring Boot로 WMS+WES를 합친 WMS/WES-lite를 구현한다. 주문 접수 → 웨이브 생성 → 피킹 태스크 할당 → AMR 배차(VDA 5050 마스터 컨트롤) → 출고 실적 집계가 범위이고, SimPy 오케스트레이터가 배차 두뇌로 결합된다.

MESManufacturing Execution System — 생산 실행 시스템

"오늘 무엇을 몇 개 만들지"(작업지시)를 받아 현장에 배분하고, 실제로 몇 개가 만들어졌는지(실적)를 집계하는 공장 운영의 두뇌.

이커머스의 주문 관리 시스템(OMS)과 구조가 유사하다. 주문(작업지시)이 들어오면 → 처리 가능한 자원(스테이션·로봇)에 할당하고 → 진행 상태를 추적하고 → 완료 실적을 집계한다. 실무 MES는 거대한 패키지 소프트웨어지만, 핵심 로직(작업지시 라이프사이클 + 자원 할당 + 실적 집계)은 웹 백엔드 기술로 충분히 구현 가능하다.

이 프로젝트에서 — 제조 도메인의 개념 참고용 항목. 물류센터인 본 프로젝트에서 이 자리는 WMS/WES가 담당한다 — "지시 접수 → 자원 할당 → 실적 집계"라는 구조는 동일하다.

디지털 트윈Digital Twin

실제 공장·설비의 상태를 반영하는 가상 복제본. 현실을 관찰하는 거울이자, "이렇게 바꾸면 어떻게 될까"를 미리 실험해 보는 공간이다.

단순 3D 모형과의 차이는 데이터 동기화다. 진짜 디지털 트윈은 현실의 측정값(사이클 타임·고장률)으로 계속 보정되고, 반대로 트윈에서의 실험 결과(배차 정책 변경, 설비 증설)가 현실 의사결정에 반영된다. 산업계에서는 물리 시뮬레이션과 통계 모델(이산사건 시뮬레이션)을 결합한 하이브리드 구조가 표준적이다.

이 프로젝트에서 — Isaac에서 실측한 작업 시간 분포를 SimPy 공장 모델에 주입하는 "캘리브레이션 결합"이 정확히 이 구조다. 물리 셀과 통계 셀이 공존하는 하이브리드가 최종형.

이산사건 시뮬레이션 · SimPyDiscrete Event Simulation

시간을 연속으로 흘리지 않고 "사건에서 다음 사건으로 점프"하며 공장의 흐름(대기열·처리량·병목)을 계산하는 시뮬레이션. SimPy는 이를 위한 Python 라이브러리다.

물리 시뮬레이션이 "로봇이 어떻게 움직이는가"에 답한다면, DES는 "센터 전체가 얼마나 잘 흘러가는가"에 답한다. AMR을 3대에서 4대로 늘리면 처리량이 얼마나 오르는지, 어느 스테이션이 병목인지 같은 질문은 DES로 수천 번 돌려 통계로 확인한다. 물류센터는 DES의 대표 적용 분야다. 창고 설계·운영 분석의 표준 방법론이 바로 이것이다. 시뮬레이션 결과가 말이 되는지 검산하는 짝꿍 도구는 Little's Law다.

이 프로젝트에서 — SimPy가 센터 물류·배차의 두뇌다. Isaac 실측치로 보정(캘리브레이션)한 뒤, 라이브 모드에서는 실시간 이벤트 기반 잡 스케줄러로 승격된다. 개발 초기의 mock publisher도 SimPy로 만든다.

Little's Law리틀의 법칙 — L = λW

안정 상태의 어떤 시스템이든 "안에 머무는 평균 개수(L) = 도착률(λ) × 평균 체류시간(W)"이 성립한다는 대기행렬 이론의 기본 법칙.

숫자로 보면 단순하다. 주문이 시간당 100건 도착하고(λ=100건/시간) 주문 하나가 창고 안에 평균 0.5시간 머문다면(W=0.5시간), 창고 안에는 언제나 평균 L = 100 × 0.5 = 50건이 처리 중이어야 한다. 분포·순서·정책과 무관하게 거의 모든 안정 시스템에 성립하기 때문에, 시뮬레이션이 뱉은 세 숫자(재공 수량·처리율·리드타임)가 이 등식을 만족하는지만 봐도 모델의 버그를 즉시 잡아낼 수 있다.

이 프로젝트에서 — 시뮬레이션 검증(V&V)의 1차 관문. SimPy 결과에서 L·λ·W를 뽑아 등식 성립을 확인하는 것이 VDI 3633 verification 활동의 구체적 실행이다(DOC 07 I1).

MQTT경량 발행/구독 메시징 프로토콜

IoT·제조 현장의 표준 메시징 프로토콜. 모든 참여자가 중앙 브로커에 연결해, 토픽 이름으로 메시지를 발행(publish)하고 구독(subscribe)한다.

HTTP가 "요청하면 응답"(1:1, 클라이언트가 물어봐야 함)이라면, MQTT는 "일어난 일을 방송"(1:N, 상태가 바뀌면 즉시 전파)이다. 헤더가 몇 바이트로 극단적으로 가볍고, 불안정한 네트워크를 견디도록 설계되어 제조·IoT의 사실상 표준이 됐다. 메시지 안에 뭘 담을지는 정하지 않기 때문에, 그 위에 Sparkplug B나 VDA 5050 같은 페이로드 표준이 얹힌다.

이 프로젝트에서 — 로봇(ROS 2)과 IT 세계(WMS·DB·웹)를 잇는 중추 신경. EMQX 브로커를 쓰고, 웹 관제 화면도 MQTT-over-WebSocket으로 같은 토픽을 직접 구독한다.

Sparkplug B설비 텔레메트리 페이로드 표준

MQTT 위에서 "설비 데이터를 어떤 토픽 구조와 형식으로 보낼 것인가"를 정한 산업 표준. 설비의 탄생·데이터·사망을 생애주기로 관리한다.

MQTT만 쓰면 팀마다 토픽 구조와 JSON 형식을 제각각 정하게 된다. Sparkplug B는 네임스페이스(spBv1.0/그룹/메시지타입/노드/디바이스), 데이터 형식(Protobuf), 상태 관리(BIRTH/DEATH)를 표준화해서, 처음 보는 설비도 구독만 하면 바로 해석할 수 있게 만든다. "설비가 지금 온라인인가"라는 제조 현장의 핵심 질문에 프로토콜 차원에서 답하는 것이 특징이다.

이 프로젝트에서 — 설비(컨베이어·소터·피킹/검수 스테이션) 텔레메트리에 적용한다. 관제 화면의 설비 온라인/오프라인 표시가 BIRTH/DEATH를 그대로 시각화한 것이다.

VDA 5050AMR 군집 통신 표준

중앙 관제(마스터 컨트롤)와 AMR들이 주고받는 메시지를 표준화한 규격. 관제가 경로를 노드·엣지 그래프로 내려주고(order), AMR이 상태를 보고한다(state).

독일 자동차공업협회(VDA)가 만든 표준으로, 서로 다른 제조사의 AMR을 하나의 관제로 묶기 위해 만들어졌다. 본래 물류·창고의 AMR 관제가 주 용도라, 물류센터 도메인에서는 중심 표준이다. 관제와 로봇의 책임 분리가 명확하다: 관제는 "어디로 갈지"(경로 그래프)를 정하고, 로봇은 "어떻게 갈지"(실제 주행·회피)를 알아서 한다. 공식 JSON 스키마가 공개되어 있어 웹 개발자에게도 친숙한 형태다. 관제가 내려줄 경로 자체를 계산하는 알고리즘 계열은 MAPF 참조.

이 프로젝트에서 — WMS/WES-lite가 마스터 컨트롤로서 order를 발행하고, AMR 쪽 커넥터가 이를 Nav2 목표로 변환해 실행한 뒤 state를 보고한다. 관제 맵의 노드·엣지 시각화가 이 표준을 그대로 그린 것이다.

AMR vs AGVAutonomous Mobile Robot · Automated Guided Vehicle

AGV는 바닥의 자기 테이프·QR 등 정해진 선로만 따라가는 운송 로봇, AMR은 지도와 센서로 스스로 경로를 계획하고 장애물을 피하는 운송 로봇이다.

AGV는 기차(선로 이탈 불가), AMR은 택시(목적지만 주면 알아서 감)에 비유된다. AMR은 레이아웃 변경에 유연하고 사람과 공존할 수 있어 물류·제조 현장에서 빠르게 AGV를 대체하는 중이다. 그만큼 소프트웨어(위치 추정·경로 계획·군집 관제)의 비중이 압도적으로 커진다. 여러 대의 경로를 부딪히지 않게 함께 푸는 문제는 MAPF, 관제와 로봇 사이의 통신 표준은 VDA 5050 참조.

이 프로젝트에서 — 옴니휠 AMR 여러 대가 랙/토트 운송(Goods-to-Person)과 예외품 리젝트 운송을 담당한다. 주행은 Nav2, 군집 관제는 VDA 5050.

Andon안돈 — 이상 알림 체계

생산 라인에 이상이 생기면 즉시 불빛·알림으로 알려 대응을 촉구하는 체계. 도요타 생산방식에서 나온 용어로, 현장 위 신호등이 원형이다.

핵심 사상은 "문제를 숨기지 말고 그 자리에서 드러내라"다. 현대의 스마트 공장·물류센터에서는 물리적 경광등을 넘어 대시보드 알림·모바일 푸시로 확장됐다. 웹 서비스의 장애 알림(PagerDuty·Slack 알림)과 정확히 같은 역할이다.

이 프로젝트에서 — 오피킹·파손 검출, 설비 이상 시 관제 포털에 Andon 알림 스트림이 뜨고, PWA 웹 푸시로 모바일에도 전달된다.

OEEOverall Equipment Effectiveness — 설비종합효율

설비가 "이론상 최대치 대비 실제로 얼마나 가치를 만들었나"를 하나의 숫자로 나타내는 제조업 대표 KPI. 가용성 × 성능 × 품질로 계산한다.

예를 들어 가용성 90% × 성능 85% × 품질 95% = OEE 72.7%. 세계적 수준의 공장이 85% 정도다. 단순 가동률보다 강력한 이유는 "돌고는 있는데 느리게 돈다", "빨리 도는데 불량을 만든다" 같은 숨은 손실이 다 드러나기 때문이다.

이 프로젝트에서 — 컨베이어·소터 등 설비 지표로 사용. 센터 전체의 중심 지표는 UPH(시간당 처리량)·피킹 정확도·주문 리드타임 같은 물류 KPI이며, 분석 화면에서 OEE와 함께 보여준다.

폐루프 품질관리Closed-Loop Quality

검수 결과가 사람 손을 거치지 않고 곧바로 물류 흐름의 변화(예외품 격리·재피킹 지시)로 이어지는 구조. "감지 → 판정 → 조치"의 고리가 자동으로 닫힌다.

많은 데모가 "AI가 문제를 찾았다"에서 끝난다(열린 루프). 진짜 스마트 물류센터의 가치는 그 판정이 자동으로 조치까지 이어지는 데 있다. 시스템 전 계층(비전 → AI → WMS → 배차 → 로봇)이 실제로 연결되어야만 가능하므로, 통합 완성도의 증명이기도 하다.

이 프로젝트에서 — 최종 데모의 대표 장면. Replicator로 만든 파손/오피킹 상황 → AI 검출 → WMS 판정 → AMR이 예외품을 리젝트 라인으로 옮기는 전 과정이 자동으로 이어진다.
