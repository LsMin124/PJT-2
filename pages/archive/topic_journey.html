SEC 00 · 한눈에 보기

일곱 번 검토하고, 여기 도착했다

최종 주제와 형태는 무엇인가한 문장 정의와 세 개의 축 — SEC 01
왜 여기에 도달했나일곱 단계의 전환과 기각 사유 — SEC 02 · 02A · 02B · 04

그림 1 · 주황은 주제 확정, 초록은 그 뒤 형태와 알고리즘의 확정. 일곱 번의 전환은 매번 "제품으로 성립하는가"를 물은 결과다.

SEC 01 · 최종 제안

결론은 요청 접수형 견적 서비스다

ONE-SENTENCE DEFINITION · 기준선 v3 §0 3PL(제3자 물류)이 AMR 도입을 결정할 수 있도록, 창고·물류 조건을 받아 시뮬레이션으로 권장 대수·기종, KPI, 검증 영상을 담은 견적서를 만들어 보내는 요청 접수형 서비스.
축 1 · 산출물

숫자와 영상이 함께 붙는 견적서

권장 대수·기종과 KPI에 배속 영상(MP4)·리플레이(JSON)·히트맵(PNG)을 붙인다. 로봇이 실제로 도는 장면이 근거로 들어간다.

축 2 · 흐름

접수 → 검수 → 발송, 8단계 비동기

접수 시 큐 순번과 예상 소요를 회신한다. 운영자는 시나리오 컴파일(②)과 리포트 검수(⑦) 두 곳에서 개입한다. 나머지는 내부 배치다.

축 3 · 신뢰 장치

같은 커널, 같은 θ, 같은 시나리오

빠른 DES와 Isaac 검증 런이 FMS 결정 커널과 θ를 공유하고, 하나의 시나리오 패키지를 소비한다. 패리티 테스트, 갭 캘리브레이션, 시나리오 해시 + 시드로 재현성을 지킨다.

SEC 02 · 확정 여정

여정 자체가 논증이다

단계방향걸린 것 → 다음으로
1 디스패처 비교 연구규칙 기반 vs 휴리스틱 vs 강화학습의 배차 성능 비교비교 연구 자체는 서비스가 아니다
2 인력 배치 전환 검토같은 할당 기술을 사람 배치 문제로응용처는 넓어졌지만 로봇 프로젝트의 정체성이 흐려짐
3 관제탑 포장로봇 운영을 웹 관제 화면으로ROS 조연화 모순 — 서비스가 주인공이 될수록 로봇 스택(ROS)이 조연으로 밀린다
4 FMS 제품화여러 AMR을 실시간 지휘하는 관제 시스템을 제품으로견적이라는 더 명확한 구매 맥락 발견 → 백로그로 이동(버린 것이 아니라 순서를 미룸)
5 견적 서비스 + SIL 검증 계층 ★제품 정체성을 "로봇을 움직이는 시스템"에서 "신뢰할 수 있는 분석"으로모순 해소. ROS는 검증 계층이라는 정직한 역할을 얻고, 웹 서비스는 온전히 주인공이 된다
  • 로봇 데모는 웹 서비스로 포장되어야 임팩트가 생긴다
  • 카테고리는 로봇 도메인 밖(견적·분석)에서 골라야 "서비스 포장"과 "ROS 주연"이 둘 다 산다
  • ROS의 정직한 역할은 검증 계층이다
SEC 02A · 여섯 번째 전환

화면 앞에서 기다리게 할 수 없었다

2026-09-02, 셀프서브 SaaS와 5분 숏런 안을 접었다. 요청은 큐에 쌓고, 운영자가 검토하고, 결과는 나중에 보낸다.

벽내용기준선 v3
GPU 1대Isaac 검증 런은 GPU 서버 1대(RTX 5080)에서 돈다. 검증 런은 GPU 런 큐로 직렬화된다. 요청이 겹치면 누군가는 기다린다§3.2 · §3.3
물리 검증은 분 단위Isaac은 실시간이라 하루치를 재생할 수 없다. 검증 런은 분 단위 미니 시나리오이고, 배리어 틱이면 실시간의 절반 이하다. 5분 안에 결과 화면을 채울 수 없다§5.1 · §6
검수 필요요청 정제·시나리오 컴파일(②)과 리포트 검수(⑦)는 운영자가 한다. 자동 응답 화면에는 이 자리가 없다§2

채택된 8단계 흐름과 v2(08-26) → v3(09-03)에서 같이 바뀐 것(파이프라인 8단계, 웹 인프라 2층, 분 단위 시나리오, 대수 그리드 스윕)은 TECH 02 시스템 아키텍처.

SEC 02B · 일곱 번째 전환

알고리즘은 하나로 고정하고, 흐름에 집중한다

MAPF를 연구 주제로 열었다가 하루 만에 "성능 좋은 것 하나로 고정"으로 정리했다. 실체는 팀 FMS 파트의 PIBT 헤딩 모델과 AI θ 2-트랙이다.

2-트랙 인터페이스 (팀 FMS 파트)

그림 2 · 주황 점선이 팀 계약의 경계. θ는 trial마다 추론되고, DES와 Isaac 검증 런은 같은 θ를 쓴다. 초록은 FMS 결정 커널이 붙는 실행 셸 두 종.

PIBT 헤딩 모델 요약

  • 발단 — Isaac에서 회전 중 충돌이 실측됐다. 셀 확대(2.0 m)는 도킹칸 겹침으로 기각하고, 회전을 모델에 넣었다
  • 상태 — 격자 1.0 m 유지. 로봇 상태 = (칸, 방향). 차체(iw.hub 1.44 m)가 셀보다 길어 자기 칸 + 뒤 칸 2칸 점유
  • 액션 — 대기 · 전진 · 좌/우 회전(틱 소모, 스윙 칸 예약) · 후진. 거리장은 θ 가중 다익스트라
  • 시뮬 파트에 넘어온 것 — 회전 시간 상수는 Isaac 실측으로 확정. 실행 요구 4건(스팟턴 · 경유점 오차 0.1 m · 배리어 틱 · 후진)의 진행은 WORKING T3·T4 진행

이론은 TECH 04, 커널·실행 셸 구조는 TECH 02. 벤치마크 수치는 팀 레포 3_FMS/docs/에만.

SEC 03 · 타겟

시장 1위가 아니라 구매 경로를 골랐다

타겟은 계약물류 중견 3PL의 반송·피킹 보조다. 중립 견적이 끼어들 자리는 매출 순위가 아니라 거래 방식이 정한다.

세그먼트시장 비중거래 방식중립 견적의 자리
GTP (선반 운반형) ~38% · 매출 1위 벤더가 창고 설계부터 견적까지 통째로 맡는 턴키 토탈 솔루션 거래 구조적으로 좁음 벤더가 직접 설계·견적하므로 제3자 견적이 개입할 틈이 없다 → v1 제외
반송/피킹 보조 ~25–27% 인프라 변경 없이 2~4주 배치, 소수 대(3~15대)씩 점진 도입 v1 타겟 "업체 말만 믿기 불안한데 자체 검증 역량이 없는" 고객층 — 견적 의사결정이 실제로 일어나는 곳

국내 수요의 본체는 이커머스/3PL(수도권 A급 센터 임차면적의 79%). 판단은 전 카테고리, 정밀 견적은 반송/피킹 보조 — GTP가 맞는 고객은 벤더 직행 안내(중립 라우팅). 근거는 RESEARCH 02.

SEC 04 · 기각된 이전 제안

데모가 아니라 제품이 필요했다

이전 판(REV A)의 "불 꺼진 물류센터"(무인 풀필먼트 센터의 무인 운영·자가 복구·What-if 6장면 시연)는 질문이 "무엇을 보여줄까(데모)"에서 "누가 왜 쓰는가(제품)"로 옮겨가며 기각됐다.

남긴 것 — "로봇 데모는 웹 서비스로 포장되어야 임팩트가 생긴다"는 교훈(SEC 02), 그리고 견적 스윕으로 형태를 바꿔 흡수된 What-if 시뮬레이션.

SEC 06

예상 질문과 답

Q0. 사람이 여전히 집는데(반송/피킹 보조), 자동화로서 비용 대비 효용이 낮지 않나?

"완전 무인화"가 아니라 "투입 비용당 처리량 개선"으로 보면 구도가 뒤집힌다. 수작업 피킹의 최대 시간 덩어리는 집기가 아니라 보행·운반이고, 이것을 가장 싼 로봇(무팔 AMR)이 제거한다. 가장 비싼 비정형 파지는 아직 사람이 압도적으로 싸다(검토 아카이브). GTP 대비 진입 비용이 낮아(공사 없음·2~4주·3~15대) ROI가 성립하기 가장 쉬운 구간이고, 시장의 25~27%로 실재한다. 이 회의감 자체가 서비스가 파는 답이다 — 창고마다 계산해서, 안 나오면 안 나온다고 말해 준다.

Q1. 왜 시장 1위 세그먼트(GTP)를 타겟하지 않았나?

GTP는 벤더 턴키 거래라 중립 견적이 끼어들 틈이 구조적으로 좁다. 반송/피킹 보조는 소수 대 점진 도입이라 "업체 말만 믿기 불안한" 고객의 견적 의사결정이 실제로 일어난다. 매출이 아니라 구매 경로로 골랐다 (SEC 03).

Q2. 견적 서비스면 로봇 프로젝트가 아니지 않나?

시뮬 파트가 만든 것이 답이다. T3 창고 씬 완료 — 도면(DXF)에서 그리드·USD 씬 생성, 물리 라이다와 nav2 AMCL 자기위치. T4 에이전트 뼈대 완료 — VDA 5050 브리지, order executor, 그리드 프리미티브 컨트롤러, Isaac 없이 배리어 틱 E2E 통과(가짜 로봇 7틱, 정지 오차 4 mm). 이 로봇 스택이 ⑤ Isaac 검증 런에서 실제로 돈다. 진행은 WORKING T3·T4 진행.

Q3. 시뮬레이션이 낸 숫자를 어떻게 믿나?

장치는 셋이다. ① 패리티: DES의 WMS 라이트와 검증 런의 시뮬 WMS가 하나의 시나리오 패키지를 소비하고, 골든 시나리오 패리티 테스트로 정합성을 지킨다. ② 갭 캘리브레이션: 검증 대상 구성에 한해 DES도 Isaac 검증 런과 같은 시간창으로 재실행해 비교한다. ③ 결정론: FMS 결정 커널은 시계·난수를 주입받고 I/O가 없다. 재현성 키는 시나리오 해시 + 시드, DES와 검증 런은 같은 θ.

Q4. 실시간 관제(FMS)는 왜 안 만드나?

제품은 견적이고, FMS는 시뮬 안에서 실제로 돈다. FMS 코어는 ROS 비참여 순수 Python 결정 커널(step(world, now, events) → decisions)이고, 실행 셸 2종(DES 하네스, MQTT 데몬)으로 양쪽에 붙는다. 로봇 쪽은 VDA 5050 틱을 그리드 프리미티브(스팟턴·직진·후진)로 실행한다. 파는 것은 관제 화면이 아니라 견적서다. 실시간 관제 제품화는 범위 밖.

Q5. 왜 셀프서브가 아닌가?

세 벽 때문이다 — GPU 서버 1대(검증 런이 GPU 런 큐에서 직렬), 분 단위 물리 검증(배리어 틱이면 실시간의 절반 이하), 운영자 검수(②·⑦). 화면 앞에서 기다리게 할 수 없어, 접수 시 큐 순번·예상 소요를 회신하고 견적서는 나중에 보낸다. 상세는 SEC 02A.
