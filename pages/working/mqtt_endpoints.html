SEC 00 · 한눈에

브로커 하나, 계정 다섯 종, 붙는 주체 여섯

SEC 02 · 붙지 않는 것

MQTT가 아닌 채널과 그 경계

구성요소대신 쓰는 채널왜
견적 BE (Spring, 상시) · React FE · PostgreSQL · MinIOREST · WS · JDBC · S3 API상시 견적 서비스는 런 스코프 시뮬 스택과 층이 다르다. 런 결과는 AMQP 결과 이벤트 → PG
견적 BE ↔ 계산엔진(DES 워커)RabbitMQ · sim.request / sim.result잡 큐(우선순위 · DLQ · CPU 워커 수평 확장). 시뮬엔진연동API명세서 §1
DES 워커 → GPU 런 큐큐에 요청 적재만큐의 유일한 소비자는 host-orch. 워커는 MQTT를 모른다
Isaac warehouse_sim.pyDDS · /cmd_vel /odom /scan /tf에이전트가 DDS ↔ VDA 5050 을 번역한다. Isaac 자체는 브로커를 모른다
WMS 수요 생성 시작 신호REST POST /run/{id}/start (host-orch → WMS)fms-core RUNNING 확인 뒤에만 주문이 나오도록. MQTT 제어 토픽이 아니다 (결정 11)
Jenkins · CIcompose 로 브로커를 띄워 테스트만test_acl_matrix.py 스테이지. 배포 파이프라인은 브로커에 붙지 않는다

접속 규칙

항목값
clientId · username같은 값. 에이전트 = 시리얼, 나머지 = edge_node_id / host_id. amr 풀은 비밀번호 하나
세션clean session · MQTT 3.1.1 · keepalive 30 s (sim-runner 60 s)
QoS상한 1. QoS 2 발행은 브로커가 거부
