SEC 01 · T3 창고 씬

그리드가 곧 씬 — 도면 한 장에서 씬·지도·격자가 나온다

SEC 02 · T4 에이전트

스티칭 규칙 (OrderBook)

  • 1틱 = 업데이트 1개 — 같은 orderId, orderUpdateId를 1 올리고 노드 하나를 더 released로 보낸다
  • 이어 붙이는 지점 — 업데이트의 첫 노드는 현재 마지막 base 노드(nodeId·sequenceId 동일)여야 한다. 아니면 거절
  • 새 orderId — base가 끝난 뒤에만 받는다. 진행 중이면 cancelOrder 먼저
  • 첫 노드 거리 — 새 order의 첫 노드는 현재 위치에서 0.5 m 이내(노드 allowedDeviationXY가 있으면 그 값)
  • 형식 검증 — 노드 sequenceId 짝수·증가, 엣지는 노드-1개, released 노드 뒤에 released 노드 금지, 엣지 released는 끝 노드와 일치
  • 취소 — 아직 도달하지 않은 노드를 버린다. lastNode는 남겨 다음 업데이트가 이어 붙을 수 있게 한다

상태 발행 규칙

  • 변화 즉시 — order 수락·거절, 노드 도달, 일시정지, 오류 때 바로 발행. lastNodeId 변화가 곧 ack
  • 하트비트 — executor 2 Hz. 브리지는 2 s 무변화 시 마지막 state 재발행
  • 거절 사유 — errors[]에 validationError · orderError · primitiveError로 남기고 state로 보고
  • 접속 상태 — connection 토픽 retained. 브로커가 끊김을 감지하면 LWT로 CONNECTIONBROKEN
쉽게 말하면 FMS는 한 번에 한 칸만 허락한다. 에이전트는 그 한 칸을 "돌기 → 직진 → 돌기"로 쪼개 실행하고, 도착하면 도착했다고 알린다. 모든 로봇이 알리면 FMS가 다음 칸을 준다.

90° 회전 틱2.3 s제자리 회전 + 정착 판정 포함

파랑 막대 = 가짜 로봇 E2E 실측, 주황 점선 = FMS의 틱 길이 가정. 두 프리미티브 모두 가정의 두 배를 넘습니다.

해석

  • 틱 길이 — 램프 1.0 m/s²와 최고 0.8 m/s에서 1 m 칸은 가속·감속 구간이 대부분이다. 회전은 정착 판정까지 포함한다. 둘 다 FMS의 1 s 가정보다 길다
  • 실행 속도 — 배리어 틱이면 Isaac 검증 런은 실시간의 절반 이하로 돈다. 검증 런을 분 단위 미니 시나리오로 잡은 이유와 맞물린다(기준선 §1·§6)
  • 회전 시간 상수 — FMS 헤딩 모델의 회전 틱 수(TURN_TICKS)는 Isaac 실측으로 확정해야 한다(§4.2). 가짜 로봇 값은 상한 추정으로만 쓴다
  • 배리어 방식 — lockstep인지 고정 주기인지, 타임아웃 처리와 시뮬 시각 기록은 FMS 파트가 확인 중이다(§9). 에이전트 쪽 ack 구현은 방식과 무관하게 동일
SEC 04 · FMS 요구 4건

요구 4건 중 3건 구현, 배리어 방식은 재확인 중

FMS 파트가 Isaac 실행에 요구한 4건과 시뮬 파트의 실측 과제 1건의 상태다(기준선 §5.2).

요구상태근거
스팟턴 — 셀 중심 정지 · 제자리 회전 · 직진T4 구현TurnController + DriveController, MovePrimitive TURN/DRIVE
경유점 오차 ≤ 0.1 mT4 구현E2E 4 mm. 노드 허용치 0.05 m로 요구의 절반
틱 배리어 동기ack 구현 · 방식 확인 중에이전트는 lastNodeId ack를 즉시 발행. lockstep/고정 주기 선택은 FMS 파트
후진 1칸 프리미티브T4 구현엣지 orientation π 판정 → 헤딩 유지 후진
iw.hub 앞축 위치 · 회전 각속도 실측완료2026-09-06 실측(sil/calibration/turn_probe/): 회전 중심 = 구동축 = 포즈 원점(이탈 ≤ 1.3 cm), 앞 0.40 m · 뒤 1.03 m 돌출 → 뒤 칸 1개 점유 · 스윙 반경 1.09 m, 각속도 지령 대비 95~97 %, 90° 폐루프 1.9 s

FMS 헤딩 모델(격자 1.0 m, 자기 칸 + 뒤 칸 2칸 점유, 회전은 틱 소모)의 상수 두 개가 이 실측에 걸려 있습니다. 인터페이스는 TECH 04, 결정 목록은 TECH 05.

SEC 05 · 실행 방법

브로커, 에이전트, 가짜 FMS 세 줄로 재현한다

Isaac 없이 E2E를 돌리는 명령과, Isaac을 상대로 붙이는 명령이다. README의 명령 그대로다.

T4 에이전트 — Isaac 없이 E2E — 펼쳐 보기 
cd sil/t4_agent
source /opt/ros/humble/setup.bash
colcon build --symlink-install && source install/setup.bash

# 1) 브로커 (EMQX 대용 로컬)
amqtt   # ~/.local/bin, 1883

# 2) 에이전트 + 가짜 로봇 (Isaac 없이)
ros2 launch amr_agent agent.launch.py serial:=amr01 fake_robot:=true

# 3) 가짜 FMS — F 전진 · B 후진 · L/R 회전, 한 노드씩 배리어 틱
python3 -m amr_agent.tools.fake_fms --serial amr01 --plan F,F,L,F,B

fake_fms는 틱마다 ack 지연·위치 오차·헤딩 오차를 출력하고, 허용치 안이면 종료 코드 0을 돌려줍니다. amqtt는 Python MQTT 브로커입니다.

T4 에이전트 — Isaac 상대 — 펼쳐 보기 
# Isaac 상대 (warehouse_sim.py + loc.launch.py 가 떠 있을 때)
ros2 launch amr_agent agent.launch.py serial:=amr01 flat_topics:=true pose_source:=odom use_sim_time:=true

flat_topics는 Isaac이 네임스페이스 없이 내는 /odom /cmd_vel에 리매핑합니다. 다중 로봇 네임스페이스는 SEC 06.

T3 창고 씬 — 빌드 · 시뮬 · 자기위치 — 펼쳐 보기 
# 선행: sil/t3_warehouse_map/map/ 에서 warehouse_layout_v5_5_final.py 실행 (npy 생성)
cd ~/isaacsim && ./python.sh <repo>/sil/t3_warehouse/build_scene.py

# 씬 + iw.hub + 물리 라이다, ROS2 개통 (서버)
source /opt/ros/humble/setup.bash
cd ~/isaacsim && ./python.sh <repo>/sil/t3_warehouse/warehouse_sim.py

# localization (별도 셸): map_server + AMCL + foxglove_bridge(8765)
ros2 launch <repo>/sil/t3_warehouse/ros2/loc.launch.py

전제: warehouse_scene.usd 존재. 동시 실행은 원본 구성 2개 · 경량 구성 6개까지(9/5 실측, WORKING · MEASURE). 관전은 Foxglove ws://<서버>:8765 또는 http://<서버>:8211/.
