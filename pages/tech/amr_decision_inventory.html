권고는 제안, 기준선 v3가 우선이다

"구현 전에 정해야 할 결정을 A~J 열 묶음으로 나누고, 항목마다 채택·상태·근거를 적은 목록." 근거는 전부 기준선 v3의 절 번호다.

기준선 개정 (2026-09-03)REV C. 2026-08 인벤토리(SimPy·Kafka·RL 디스패처 전제)를 기준선 v3로 전면 교체했다. 바뀐 축은 제품 형태(요청 접수형), 웹 인프라 2층, 메시징(RabbitMQ + EMQX, Kafka 없음), 저장소(PostgreSQL + H2 + MinIO), FMS(PIBT 헤딩 모델 + θ), 로봇 실행(VDA 5050 틱 = 그리드 프리미티브), 탐색(대수 그리드)이다. 근거: 기준선 v3 §1, 다이어그램 원본 FMS-WMS 통합 아키텍처 v3.10.

시스템 지도 — 결정 A~J가 걸리는 자리

파랑 프레임이 EC2, 초록 프레임이 GPU 서버다. 주황 상자는 두 WMS가 함께 쓰는 시나리오 패키지, 초록 점선은 Isaac 실측을 DES에 되먹이는 갭 캘리브레이션이다. 괄호의 알파벳이 이 문서의 섹션이다. J(검증·운영)는 상자 하나가 아니라 그림 전체에 걸리는 규칙이다. 상세 구성은 TECH 02 시스템 아키텍처.

이 문서를 읽는 법 각 행의 "채택"은 기준선 v3의 결정을 옮긴 것이다. 권고는 제안이고, 서술이 충돌하면 기준선 v3가 우선한다. 팀원 파트(FMS 알고리즘·AI·웹 BE)는 계약·상태·역할만 적는다. 내부 구현과 벤치 수치는 팀 레포 3_FMS/docs/를 본다.

SEC D · FMS (인터페이스 수준)

FMS는 커널 하나, 셸 둘이다

FMS 코어는 시계·난수를 주입받고 입출력이 없는 순수 결정 커널이다. DES와 Isaac 검증 런이 같은 커널을 쓰고, 차이는 실행 셸 2종이 흡수한다.
