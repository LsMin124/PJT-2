SEC 01

프로젝트 정체성과 목표

쉽게 말하면로봇 데모가 아니라, 실제 물류센터가 쓰는 것과 같은 구조의 소프트웨어 시스템을 만듭니다. 다만 진짜 로봇과 창고 대신 컴퓨터 속 가상 공간을 씁니다 — 그래서 비싼 장비 없이도 7주 안에 전체를 완성할 수 있습니다.
ONE-LINE DEFINITION"멀티로봇 시뮬레이션 기반 물류센터를 구축하고 산업 계층 구조로 WMS/WES까지 통합한 스마트 물류 솔루션"

"로봇 프로젝트에 백엔드를 붙인 것"이 아니라 물류 IT/OT 통합 시스템에서 물리 레이어를 시뮬레이션으로 구현한 것. 물리 세계만 가상일 뿐, 데이터 플로우·백엔드·서비스는 실제 스마트 물류센터와 동일한 구조로 구축한다.

이 문서가 처음이라면 안내 문서(DOC 00)를 먼저 읽는 것을 권한다. 처음 보는 용어는 용어사전에서 그래픽과 함께 설명 — A 로보틱스·시뮬레이션 · B 물류센터·표준 · C AI·데이터·서비스

전략적 배경

SEC 02

SEC 04

SimPy × Isaac Sim 정합성과 통합

쉽게 말하면두 시뮬레이터는 시간을 다루는 방식이 정반대입니다. 하나는 영화처럼 매 순간을 전부 그리고(Isaac), 하나는 중요한 사건만 골라 빨리감기합니다(SimPy). 억지로 하나로 묶으면 둘 다 망가지므로, 느슨한 연결부터 시작해 세 단계로 점점 깊게 결합합니다.

근본적 차이 — 시간 패러다임

SimPy — 이산사건(DES)

  • 시간: 사건→사건 점프, 사이 구간 미계산
  • 속도: 하루치를 수 초에, Monte Carlo 수천 회
  • 관심사: 흐름과 자원 — 처리량·병목·대기열

Isaac Sim — 연속시간 물리

  • 시간: 고정 타임스텝(1/60s 등) 연속 적분
  • 속도: 실시간 ~ 수 배속
  • 관심사: 운동과 상호작용 — 파지·충돌·센서

→ 하나의 시계로 강결합 금지: DES의 장점(초고속·통계 반복)이 물리 속도에 묶여 소멸.

정합 패턴 3단계 — 점진 승격 구조

캘리브레이션 결합 OFFLINE · 우선

Isaac에서 단위 작업 반복 측정(피킹 200회 → 평균 12.3s, σ=1.8s, 실패율 4%) → SimPy 공정 파라미터로 주입. 실행 완전 분리·단방향. "물리적 근거를 가진 센터 모델" — 산업 디지털 트윈 표준 구조. what-if 실험 자유(AMR 3대 vs 4대, 배차 A vs B, 슬로팅 전략 비교).

▼ 승격

계획-실행 분리 ONLINE · 데모 핵심

SimPy = 실시간 페이싱되는 오케스트레이터(작업 도착·큐·배차 결정). 명령은 MQTT(VDA 5050 order) → Isaac 물리 실행 → 완료 이벤트 회신 → 다음 사건 트리거. 내부 예상 소요시간은 버리고 외부 완료 이벤트 대기 → 사실상 이벤트 기반 잡 스케줄러화.

▼ 승격

하이브리드 FINAL FORM

Isaac에 있는 셀 = 패턴 2 실제 실행, 나머지 셀 = 패턴 1 분포로 가상 처리. 물리 셀 + 통계 셀 공존 = VRAM 예산 해법이자 브라운필드 공장 디지털 트윈과 구조 동일. 실기체 편입 시 "실물 셀 1개 추가"로 자연 확장.

정합성 설계 원칙

  • 시간 권위 단일화 — 라이브 통합에서는 벽시계(Isaac 실시간)가 권위, SimPy가 추종
  • 경계는 이산 사건만 — 오더 발행/완료/실패만 교환. 연속 상태(관절각·좌표)는 Sparkplug B로 DB/Grafana에만
  • 실패 의미론 통일 — Isaac 파지 실패 = SimPy에서 재시도/불량 분기 동일 정의
  • 결정론 포기 + 전 사건 타임스탬프 로깅으로 사후 재구성 확보

SEC 06

단계별 로드맵

쉽게 말하면작은 완성품을 먼저 만들고 살을 붙입니다. 0단계에서 로봇 없이 데이터 흐름부터, 1단계에서 로봇 조종, 2단계에서 전체 연결 — 어느 단계에서 멈춰도 "완성된 무언가"가 남도록 설계했습니다. 3단계부터는 심화(AI 강화학습, 확장)입니다.
PRINCIPLE수직 슬라이스 우선 — "스테이션 1개 + AMR 1대 + 데이터 경로 끝까지"를 최소 구성으로 먼저 관통, 이후 수평 확장. 통합 리스크를 앞에서 흡수.
PHASE 0

데이터 백본 (Isaac 없이 시작)

SimPy 물류 모델(가짜 분포) + Spring WMS/WES-lite + MQTT 브로커 + TimescaleDB/PostgreSQL + Grafana · VDA 5050/Sparkplug B 스키마 설계 · mock publisher 가동

PHASE 1

ROS2 코어 (Gazebo)

AMR+팔 통합 URDF · ros2_control(베이스 velocity/팔 position) · Nav2 + EKF + MoveIt2 · behavior tree로 주행→도킹→피킹

PHASE 2

Isaac Sim 포팅 + 수직 슬라이스 완성

USD 변환·ROS2 브리지로 노드 재사용 · 피킹 스테이션 1 + AMR 1 라이브 접속(패턴 2) · Replicator 합성 데이터 → 검수 모델 → 폐루프

PHASE 3

Isaac Lab RL

SEC 07

Sim-to-Real 사이드 트랙 — 하드웨어 계획

쉽게 말하면시간이 남으면 작은 실물 로봇(로봇팔 + 바퀴 베이스)을 사서 가상 세계에 연결해보는 선택 과제입니다. 무엇을 살지, 언제 살지(가상에서 충분히 검증된 시점), 무엇이 어려운지를 미리 정리해둔 섹션이라 — 지금 당장 읽지 않아도 됩니다.

플랫폼 확정: SO-101 (팔) + LeKiwi (베이스)

  • SO-101: LeRobot 생태계 표준 오픈소스 6DOF 매니퓰레이터
  • LeKiwi (UIUC SIGRobotics): SO-101을 싣도록 설계된 3륜 옴니휠(키위 드라이브) 홀로노믹 베이스
  • 결정 근거: 팔·베이스가 같은 STS3215 + 같은 컨트롤 보드 + 같은 SDK로 통합, ros2_control 커뮤니티 구현체·Isaac 에셋 양쪽 존재, 옴니휠 AMR 구상과 정합

운용 원칙

  • 구매 트리거: Isaac Lab 정책이 랜덤화 폭 확대에도 안정 성공률(80%+) 유지 시점 = 주문 시점 (배송/조립 2~4주 감안해 선주문)
  • 시뮬 단계부터 실기체 URDF(LeKiwi+SO-101) 기준으로 모델 고정 → 전이 시 "모델 그대로, 갭 파라미터만 보정"

  • 갭 분석 기록이 곧 핵심 산출물: 랜덤화 항목별(마찰·질량·액추에이터 지연·관측 노이즈) 성공률 변화, 시뮬 vs 실기체 갭, 서보 백래시·통신 지연 영향, 실물 응답 특성(계단 명령 정착 시간) 측정 → 시뮬 파라미터 반영 과정
SEC 08

이론 학습 전략 — Just-in-Time

쉽게 말하면수학·이론 공부는 교과서 정주행 대신, 프로젝트에서 그 이론이 실제로 필요해지는 순간에 최소한만 배웁니다. 미리 해둘 것은 딱 하나(모터 제어의 기본인 PID 감 잡기, 2~3일)뿐입니다.

원칙: 교과서 정주행(현대제어·라그랑주 동역학 등)은 오버. 프로젝트 단계가 이론을 소환하는 시점에 최소 구현으로 학습. 별도 트랙 없음.

프로젝트 단계소환되는 이론최소 구현 과제
옴니휠 베이스 제어기구학 — 키위 드라이브 역기구학, 홀로노믹/자코비안3륜 속도↔(vx,vy,ω) 변환 행렬 직접 유도 + numpy 검증 ~1일
ros2_control 튜닝제어공학 — PID1차/2차 시스템 Python PID 시뮬, 게인별 응답 관찰 ~2-3일 유일한 선행 학습
MoveIt2 매니퓰레이션로봇공학 — FK/IK, DH, 특이점SO-101 URDF 순기구학 numpy 계산
EKF 센서 퓨전상태추정 — 칼만 필터1차원 칼만 필터 직접 구현 ~반나절
Isaac Lab RL동역학 맛보기랜덤화 실험으로 체감 (깊이 불요)
  • 운용 리듬: "이번 주 작업에 등장한 이론 하나를 주말에 최소 구현으로 정리" → 산출물이 그대로 설계 근거 문서/기술 블로그
  • 효과: 담당 트랙의 이론적 근거를 직접 검증·설명할 수 있게 됨 — 파라미터 선택이 "감"이 아닌 "근거"가 된다
  • Modern Robotics 등은 정독이 아닌 사전(해당 챕터만) 용도
SEC 09

핵심 결정 사항 — Decision Log

쉽게 말하면지금까지 정한 중요한 결정들의 목록입니다. "이거 왜 이렇게 했더라?"가 궁금해지면 여기부터 봅니다. 결정이 바뀌면 이 목록에 이력을 남깁니다.
도메인 = 물류센터(풀필먼트) — 상위 시스템은 WMS/WES, 매니퓰레이션은 피스 피킹으로 유지 (REV B 전환)
프로젝트 정체성 = 시뮬 기반 물류 IT/OT 통합 시스템 (로봇 단독 프로젝트 아님)
피스 피킹 = MoveIt2 고전 접근이 본체, SKU 파지 RL은 심화 챕터
시뮬레이터 = Gazebo(개발 무대) + Isaac Sim(합성 데이터·물리 셀) + Isaac Lab(RL 1태스크) + SimPy(물류 DES)
버전 고정 = Isaac Sim 5.x / Isaac Lab 릴리스 태그 / Python 3.11 (Blackwell 제약)
머신 역할 = 5080 Ubuntu 전담 워크스테이션, 5060 Ti Windows는 원격 클라이언트
산업 표준 = 설비 텔레메트리 Sparkplug B / AMR 운송 VDA 5050 (구현은 2.x 기준)
SimPy×Isaac 통합 = 캘리브레이션 → 라이브(계획-실행 분리) → 하이브리드 점진 승격
기술 투자 배분 = 로봇/시뮬 50 / 산업 통합 30 / 서비스·앱 20
개발 순서 = 수직 슬라이스 우선, 데이터 백본 먼저 (Phase 0)
실기체 = SO-101+LeKiwi, STS3215 1/345 ×9(+예비), 12V 통일, 리더 암 불필요, 구매 트리거는 RL 정책 안정화 시점
URDF는 처음부터 실기체(LeKiwi+SO-101) 기준으로 고정
이론 학습 = just-in-time, 선행은 Python PID 시뮬 2~3일만
