SEC 01 · 왜 이 트랙인가

"시뮬+ROS2는 조연 아닌가"에 대한 답 — 맞다, 그리고 그게 설계다

제품의 주연은 견적 엔진(DES 스윕 + 원가 모델)이다. 물리 시뮬+ROS2는 조연이 맞고, 아키텍처 원칙("물리는 좁고 깊게, 견적은 넓고 얕게")이 처음부터 그렇게 배역을 나눴다. 문제는 조연이 필요하냐가 아니라, 조연이 소품으로 전락하지 않게 하는 규율이다.

역할내용
① 견적의 증거 층DES 숫자는 가정 위의 숫자다. 벤더도 아닌 우리가 "이 대수면 이 처리량"을 주장하려면 근거가 필요하고, 물리 검증은 그 근거를 직접 측정한 오차 모델로 만든다. 벤더 공개 수치로 보정하는 대안도 있으나, 그 수치는 판매용이라 중립·검증 서사와 충돌한다
② 발표·영업 자산제안서 생성기의 차별점은 "고객 도면 위에서 실물 상용 기종이 굴러가는 장면"이다. 팀 관점에서도 6인 구성(로봇/시뮬 트랙 보유)과 발표 평가에서 웹앱+수식만으로는 기술 볼륨이 부족하다
③ 성장 경로VDA 5050 어댑터는 견적 도구가 훗날 실로봇·실FMS와 붙는 인터페이스다. 견적 → 도입 검증 → 운영 보조로 자라는 길이 이 트랙에 있다
④ 업계 명칭이 있다 — Virtual Commissioning 2026-08-25 추가이 트랙은 업계 표준 관행인 가상 시운전(VC)의 SiL 구성과 일치한다 — 실제 제어 소프트웨어(FMS)를 가상 플랜트(Isaac 창고+로봇)에 물려 실 설치 전에 검증하는 방식. VDI/VDE 3693이 모델 유형·용어를 표준화했고, Siemens는 AGV 시스템 VC와 가상 환경에서의 AMR 함대 규모 평가·최적화를 공식 워크플로로 제공한다 — 우리 제품이 서는 지점과 동일하다. 업계 자료는 배치 기간 단축(~30% 보고 사례)을 근거로 VC를 권장 관행으로 다룬다
전락 조건과 방어영상만 찍고 수치를 돌려주지 않는 순간 이 트랙은 장식이 된다. 방어는 SEC 00 원칙 2 — 매 태스크가 DES 보정 수치로 끝난다. 반대로 시간이 부족하면 축소선도 명확하다: T4를 잘라 T3까지만 해도 제품(견적+단일 로봇 물리 검증)은 성립한다(SEC 07)
SEC 02 · 공통 기반 (T0)

제로에서 시작하지 않는다 — 검증된 자산 위에서 출발

항목내용
실행 환경홈서버 (32GB · RTX 5080) · Isaac Sim 6.0.1 (~/isaacsim) · ROS2 Humble (/opt/ros/humble) · Isaac 동시 1인스턴스 규칙
브리지isaacsim.ros2.bridge 확장 — 시스템 Humble을 소싱한 뒤 Isaac 기동(외부 노드와 같은 DDS 도메인). RMW는 미설정 = Fast DDS 기본, ROS_DOMAIN_ID 통일
검증된 자산iw.hub 공식 USD(조인트 구조 확인: 차동 2륜 + 캐스터 4 + 리프트) · full_warehouse 씬(전 메시 콜라이더 확인) · 주행 데모 스크립트(WheeledRobot + DifferentialController, 2026-08-24 실구동) — 기준 기종 문서
학습 전이colcon·launch·URDF 경험은 ROS2 랩 노트에서 계승. 시뮬 시간 규율: 전 노드 use_sim_time, /clock은 Isaac이 발행
시각화 (헤드리스 제약)이 서버는 X 없음 → RViz2 직접 실행 불가. 대안 2개: ① Isaac 뷰포트를 WebRTC 스트리밍으로(검증 경로) ② foxglove_bridge(웹소켓 8765)를 띄우고 노트북 브라우저에서 토픽 시각화 — tailscale 경유
SEC 03 · TASK 1

Teleop — 키보드로 iw.hub 한 대를 몬다

항목내용
목표기존 데모의 스크립트 직접 제어를 ROS2 토픽 제어로 교체 — 브리지 파이프라인 개통이 본질
구현 골자간단 씬에 iw.hub 로드 → OmniGraph 액션 그래프 구성: /cmd_vel 구독 → 차동 컨트롤러(바퀴 반경 0.115m·축간 0.413m, 실측 확인값) → 아티큘레이션, 그리고 /odom·/tf·/clock 발행. 외부에서 teleop_twist_keyboard로 조종(터미널 기반이라 SSH만으로 충분)
완료 기준SSH 키 입력으로 전진·후진·회전 동작 / ros2 topic hz로 /odom·/clock 주기 확인 / 스트리밍 클라이언트 육안 확인
DES 환류필수 최고 속도·가감속 곡선 실측 → robot_landscape 파라미터 시트의 iw.hub 추정값 1차 보정
예상 함정/clock 미발행 시 외부 노드 시간 정지(use_sim_time 확인) · cmd_vel 부호/좌표계 뒤집힘 · 브리지가 시스템 Humble 대신 내장 라이브러리를 잡는 소싱 순서 문제
예상 소요2~3일 (추정)
SEC 04 · TASK 2

Nav2 자율주행 — 목표점을 주면 알아서 간다

항목내용
목표간단 씬(장애물 몇 개)에서 NavigateToPose로 A→B 자율주행. Nav2 풀스택을 한 번 온전히 돌려 스택을 이해하는 학습 단계
구현 골자iw_hub_sensors 변형 USD(라이다 포함) 사용 → 라이다 토픽 발행 추가 → Isaac 오큐펀시 맵 생성기로 맵 추출(PNG+YAML) → nav2_bringup(map_server·planner·controller·bt_navigator). 위치는 1차로 그라운드 트루스(map→odom 고정)로 단순화, AMCL은 여력 시 비교 실험
완료 기준목표점 5곳 연속 도달 / 경로상 장애물 회피 확인 / foxglove로 코스트맵·경로 시각 확인
DES 환류필수 직선·코너 구간별 주행시간 실측 vs DES 1m 셀 이동 모델 → 오차율 첫 데이터
예상 함정TF 트리 구성(map→odom→base_link 책임 분리) · 라이다 토픽 타입(LaserScan vs PointCloud2)과 Nav2 설정 불일치 · 이 단계는 글로벌 플래너 ON이 정상 — T4에서 OFF로 전환됨을 미리 인지
예상 소요4~5일 (추정)
SEC 05 · TASK 3

물류 씬 투입 — 창고에서 반송 사이클을 돈다

항목내용
목표full_warehouse에서 스테이션 A↔B 반복 반송 — 데모(demo.html)의 파킹·스테이션 개념과 좌표 체계를 맞춘다
구현 골자창고 오큐펀시 맵 생성 → 스테이션·파킹 좌표 정의 → 왕복 반송 루프(NavigateToPose 연쇄) → 사이클 타임 로거. 리프트 조인트 적재·하역 연출은 옵션(발표 장면용)
완료 기준왕복 반송 20회 무충돌 완주 / 사이클 타임 로그 자동 수집
DES 환류필수 사이클 타임 분해(주행/회전/정지·재출발) → DES의 속도·회전 페널티 파라미터 보정. 여기서 나온 값이 견적 엔진 신뢰도의 첫 실증
예상 함정3,473 콜라이더 씬에서 코스트맵 해상도·갱신 주기 튜닝 · 좁은 랙 통로의 팽창 반경 설정 · RAM은 Isaac 16GB + Nav2 1대라 여유(SEC 04)
예상 소요3~4일 (추정)
SEC 06 · TASK 4

다중 로봇 — 표준 아키텍처(중앙 하달)로 전환한다

항목내용
목표3~5대 + FMS 스텁의 첫 결합 — 여기서부터가 우리 아키텍처의 본 모습이다. 로봇의 자율 경로계획을 끄고 중앙이 경로를 하달한다
구현 골자네임스페이스 분리(/robot1…) · 로봇별 Nav2를 컨트롤러 모드로 전환(글로벌 플래너 OFF, FollowPath/NavigateThroughPoses로 경로 주입) · FMS 스텁(간단 중앙 하달기 — 팀 MAPF 로직이 붙기 전의 대체) · VDA 5050 어댑터 초판(order 하달·state 보고, MQTT)
완료 기준3대가 교차 경로에서 중앙 하달 경로로 무충돌 운행 / 어댑터 경유로 상태가 MQTT에 올라옴 / 경로 막힘 시 재계획 없이 FMS 보고 동작
DES 환류필수 다중 로봇 간섭 실측(합류 대기·양보 시간) → DES 간섭 계수 보정. 부가로 Nav2 대당 RAM/CPU 실측 → 런타임 아키텍처 SEC 04 추정치를 실측 칩으로 교체
예상 함정네임스페이스별 TF 충돌(frame 이름 접두) · /clock 단일화 · DDS 참가자 수 증가 시 디스커버리 지연 · 대수 확대는 스케일 사다리(런타임 아키텍처 SEC 05) 적용
예상 소요5~7일 (추정)
T4가 끝나면SIL 트랙이 팀 FMS(MAPF)와 결합할 소켓이 완성된다 — FMS 스텁 자리에 실제 디스패처를 꽂으면 검증 런 파이프라인이 된다. 이후는 로드맵 밖: 보정 루프 반복, 최적 구성 검증 런, 발표 장면 촬영.
SEC 07 · 리스크와 축소선

어디서 멈춰도 제품은 성립한다

시간 압박 시나리오축소선그때도 남는 것
