SEC 01

인덕션은 세 가지 일을 동시에 한다

쉽게 말하면 분류기(소터)는 "한 줄로, 한 개씩, 간격 맞춰" 들어오는 상자만 처리할 수 있습니다. 하차된 상자 무더기를 그 상태로 바꿔주는 공정이 인덕션입니다. 무더기 → 한 줄 정렬이라는 변환이 핵심입니다.
기능내용실패하면
싱귤레이션
singulation		겹치거나 나란히 붙은 상자를 낱개로 분리해 한 줄로 만든다2개가 붙은 채 스캐너 통과 → 미스캔 → 리젝트 라인행
정렬·간격 확보운송장 면이 스캐너를 향하도록 돌리고, 상자 사이 간격을 소터 투입 규격에 맞춘다간격 부족 → 소터 캐리어 탑재 실패 → 재순환
투입 타이밍순환 중인 소터 캐리어의 빈 칸에 맞춰 상자를 밀어 넣는다타이밍 불일치 → 캐리어가 빈 채로 지나감 (용량 낭비)

기계식 설비가 대부분을 처리하지만, 겹침 해소와 비정형물 정리는 여전히 인덕션 라인의 작업자 몫이다. 그래서 이 공정의 처리율에는 "사람 손 속도"라는 상한이 걸린다.

SEC 02

처리량 체인 — 병목은 구조적으로 인덕션에 온다

허브의 시간당 처리량은 직렬 공정 중 가장 느린 단계가 정한다. 각 단계의 용량 특성을 나란히 놓으면 병목의 위치가 보인다.

① 하차
도크 수 × 도크당 하차 속도. 인력 작업이라 확장하려면 사람을 더 투입해야 한다 (심화 A)
인력 비례
② 인덕션
라인 수 × 라인당 투입 속도. 겹침 해소·정렬에 사람 손이 필요해 라인당 속도에 상한이 있다. 라인 증설은 공간·인력 제약
병목 후보 1순위
③ 스캔·계측
다면 스캐너·DWS(크기·무게·바코드 동시 계측기)는 컨베이어 속도로 처리 — 기계 용량이 크고 병목이 되는 일이 드물다
기계 용량
④ 소터
캐리어 속도 × 캐리어 피치(칸 간격)로 정해지는 기계 용량. 크로스벨트 소터(캐리어마다 달린 작은 벨트가 상자를 옆으로 밀어내는 방식)는 벤더 공개 자료 기준 시간당 수만 개 수준 (Interroll·BEUMER 등)
기계 용량 (큼)
⑤ 슈트·상차
슈트 버퍼가 차면 소터가 해당 슈트에 부릴 수 없어 재순환 — 상차 인력 속도가 뒤에서 미는 병목이 될 수 있다
버퍼 + 인력
  • 구조적 결론 — 소터(④)는 돈으로 용량을 살 수 있는 기계지만, 인덕션(②)은 낱개 분리라는 비정형 작업 때문에 기계화가 덜 됐다. 그래서 소터가 굶는(starvation) 형태의 병목이 전형적이다
  • 수치 감각 — 곤지암 메가허브의 처리 능력은 하루 175만 개다. 가동이 심야 수 시간에 집중되는 것을 감안하면 피크 시간당 십수만 개를 여러 인덕션 라인이 나눠 감당해야 한다는 계산이 나온다 (공개 수치 출처)
  • 이형물의 이중 타격 — 이형물은 인덕션에서 별도 라인으로 빼는 작업 자체가 인덕션 속도를 깎는다. 심화 A의 문제가 여기서 다시 나타난다
SEC 03

대기열 이론 관점 — 피크가 왜 치명적인가

쉽게 말하면 처리 능력의 90%만큼 물량이 들어올 때와 99%만큼 들어올 때, 대기 시간은 10% 차이가 아니라 수 배~수십 배 차이가 납니다. 혼잡은 용량에 가까워질수록 비선형으로 폭발합니다. 피크 시간대가 문제인 이유가 이것입니다.

기호부터 — 세 개면 충분하다

대기행렬 수식에 쓰는 기호는 아래가 전부다. 예시 값으로 감을 잡고 수식을 읽으면 어렵지 않다.

기호뜻예시 값
λ (람다)도착률 — 시간당 들어오는 상자 수시간당 9,000개 도착
c서버 수 — 병렬로 일하는 인덕션 라인 수5개 라인
μ (뮤)처리율 — 라인 1개가 시간당 처리하는 상자 수라인당 시간당 2,000개
ρ (로)가동률 = λ ÷ (c×μ) — 전체 처리 능력 중 얼마나 차 있는가9,000 ÷ (5×2,000) = 0.9 → 능력의 90%를 쓰는 중
  • 대기의 비선형 폭발 — 대기 시간은 대략 1/(1−ρ)에 비례한다(M/M/c — 도착과 처리가 모두 무작위인 창구 c개짜리 표준 대기행렬 모형의 성질). 위 예시로 계산하면 ρ=0.9일 때 1/(1−0.9)=10배, ρ=0.99면 100배. 물량이 10% 늘었을 뿐인데 대기는 10배로 뛴다
  • 비정상 도착 — 택배 도착은 하루 안에서 심하게 출렁인다(간선차 도착 스케줄에 따라 몰림). 평균으로 계산하면 안전해 보여도 피크 구간에서는 ρ>1이 되어 대기열이 무한정 자란다 — 버퍼(컨베이어)가 차면 하차까지 거꾸로 막힌다(blocking)
  • 해석의 한계 — 수식 모델(M/M/c)은 감을 잡는 용도다. 실제로는 처리 시간이 수식의 가정(지수분포)과 다르고, 공정이 직렬로 얽혀 있고, 버퍼가 유한하다 → 그래서 시뮬레이션(DES, 이산사건 시뮬레이션)이 필요하다 (SEC 05)
SEC 04

싱귤레이터 기술 — 기계식과 로봇식

병목의 원인인 싱귤레이션(낱개 분리)을 푸는 세 갈래 접근이다. 어느 쪽이든 "겹침을 얼마나 빨리 푸는가"가 관건이다.

방식원리한계
기계식 싱귤레이터 속도가 다른 벨트를 병렬·직렬로 배열해 상자들이 자연히 한 줄로 벌어지게 만든다. 정렬 컨베이어·경사 롤러 조합 완전히 겹친(포개진) 상자는 못 푼다. 비닐·마대는 벨트에서 미끄러져 오작동. 잔여 겹침은 결국 사람이 푼다
비전 + 로봇식 카메라로 무더기를 인식하고 로봇팔(흡착)이 한 개씩 집어 투입 — 파렛트·벌크에서 소포를 낱개 투입하는 상용 사례로 Ambi Robotics 등 처리율이 파지 사이클 시간에 묶인다. 겹침·비정형 인식은 심화 C의 인식 문제와 동일 — 여기서 두 심화 주제가 만난다
운영적 해법 기술 대신 흐름 제어로 — 간선차 도착 스케줄 평탄화, 하차 속도 조절로 인덕션에 맞춰 공급 상류(발송 터미널·간선 운행)와의 조정이 필요해 허브 단독으로는 한계
SEC 05

SimPy 모델 설계 — 구체안

허브 1개 라인을 SimPy로 모델링하는 설계안이다. 목적은 "인덕션 처리율·라인 수가 전체 처리량과 체류 시간에 미치는 영향"의 정량화다.

모델 구성 요소

요소정의파라미터 (출처)
엔티티시뮬레이션 안을 흘러다니는 개체. 여기서는 상자 — 속성: 도착 시각, 크기 등급(대/중/소), 목적지 슈트, 이형물 여부크기 비율: 소형 약 90% (CJ 공개 자료)
도착 과정간선차 단위 배치 도착 — 차 1대 = 상자 수천 개가 하차 속도로 풀려나옴. 차량 도착은 시간대별 스케줄시간대 분포: NLIC 월별 통계 + 심야 집중 가정을 명시
자원 1 · 하차 도크Resource(capacity=도크 수) — 차량이 도크를 점유하차 속도: 심화 A의 공개 수치 범위로 시나리오화
자원 2 · 인덕션Resource(capacity=라인 수) — 상자별 처리 시간은 로그정규분포(대부분 짧지만 가끔 아주 긴 값이 나오는, 오른쪽 꼬리가 긴 분포). 겹침·이형물이면 길어짐평균 처리 시간은 미지수 → 실험 변수로 두는 것이 이 모델의 목적
자원 3 · 소터용량 C의 순환 컨베이어 — Store로 캐리어 슬롯을 표현, 슈트 만차 시 재순환용량: 벤더 공개 범위(시간당 수만 개)에서 설정
버퍼하차→인덕션 사이 유한 버퍼 — 차면 하차 중단(blocking)길이는 레이아웃 가정으로 명시

코드 골격 (개념 스케치)

# 상자 1개의 여정: 하차 버퍼 → 인덕션 → 소터 → 슈트
def box_flow(env, box, buffer, induction, sorter, stats):
    yield buffer.put(box)                        # 하차 (버퍼 만차면 여기서 블로킹)
    t_in = env.now
    with induction.request() as line:            # 인덕션 라인 점유
        yield line
        t = lognormal(MEAN_INDUCT, SIGMA)
        if box.is_irregular: t *= IRREGULAR_FACTOR
        yield env.timeout(t)                     # 낱개 분리·정렬·투입
    yield sorter.slots.get()                     # 빈 캐리어 대기 (소터 굶주림이 여기서 보임)
    yield env.timeout(RIDE_TIME)
    stats.record(wait=env.now - t_in, box=box)   # 체류 시간 기록

전체 모델은 여기에 간선차 도착 스케줄러, 슈트 만차 → 재순환 분기, 시간대별 통계 수집이 붙는다. 핵심은 구조가 아니라 파라미터의 출처를 명시하고, 미지 파라미터는 실험 변수로 돌리는 규율이다.

SEC 06

실험 설계 — 무엇을 돌려서 무엇을 얻나

SEC 05 모델로 돌릴 실험 4개다. 각 행은 "무엇을 바꾸면(조작 변수) → 무엇이 어떻게 변하는지(관측 지표)"로 읽는다.

실험조작 변수관측 지표
① 병목 위치 확인 인덕션 라인당 처리율을 범위로 스윕 소터 공회전율(빈 캐리어 비율), 시간당 총 처리량 — 처리율이 어느 값 아래에서 소터가 굶는지 곡선으로 제시
② 증설 비교 인덕션 라인 수 +1 vs 라인당 속도 +20% (같은 투자라 가정) 처리량·평균 체류 시간·버퍼 블로킹 시간 — 어느 쪽 투자가 효과적인지
③ 피크 민감도 도착 집중도(피크 시간 폭)를 조절 최대 대기열 길이, 마감 시각까지 처리 완료율 — SEC 03의 비선형 폭발을 수치로 재현
④ 이형물 비율 영향 이형물 비율·처리 시간 배수를 조절 전체 처리량 하락 폭 — "이형물 사전 분기"의 가치를 정량화 (심화 A SEC 04와 연결)
  • 검증 규율 — 각 실험은 난수 시드를 바꿔 반복(replication)하고 평균±신뢰구간으로 보고한다. 1회 실행 결과로 결론 내리지 않는다
  • 캘리브레이션 — 공개 수치(일 175만 개 등)와 총량이 대략 맞는지로 모델의 스케일을 점검한다. 맞지 않으면 파라미터 가정을 문서에 남기고 수정한다
  • 산출물 — "인덕션 처리율 vs 소터 공회전율" 곡선 1장이 이 심화 문서 전체의 결론을 요약하는 그림이 된다
